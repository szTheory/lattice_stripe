<objective>
Prove that the six verbs this phase ships actually route — against `stripe-mock`, a real HTTP server
generated from Stripe's own OpenAPI spec — and hand Phase 65 the fixture promotion contract it needs.

Purpose: the Mox unit tests prove the SDK *constructs* the right requests. They cannot prove Stripe
accepts them. `stripe-mock` closes exactly that gap: real routing, real JSON decode, real
`%Response{}` and `%List{}` shapes. It deliberately does **not** close the pagination gap — it
returns one synthetic item per list and ignores `limit` and `starting_after` — so pagination stays a
Mox-proven property and that limitation is recorded honestly rather than papered over.

There is no capability question to probe here: all six verbs were exercised against
`stripe/stripe-mock:latest` v0.199.0 during research, and `DELETE` on a feature returned 404. So this
plan carries no capability probe and no `@tag :skip`, because a probe's failure mode is a silent skip
— the fake-green this project has explicitly recorded values against.

Output: the integration suite, and one appended line to Phase 65's build constraints in ROADMAP.md.
</objective>
