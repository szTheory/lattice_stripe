<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Checkout/browser redirect -> provisioning truth | The browser can report a "success" path before the authoritative subscription or invoice state is safe to trust |
| portal session URL -> account access | `session.url` is effectively a bearer credential and misuse would create an operator/security footgun |
| flagship recipe -> canonical surface guides | A fuller recipe can accidentally overclaim or compete with the canonical guides if routing is sloppy |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-01 | T | recurring-billing provisioning story | mitigate | State clearly that Checkout success redirects are UX-only and webhook-confirmed lifecycle events drive provisioning truth |
| T-45-02 | T | customer creation and signup flow | mitigate | Recommend customer reuse explicitly so the guide does not normalize duplicate customers or duplicate subscriptions |
| T-45-03 | I | portal session handling and product limits | mitigate | Call out bearer-URL handling and present portal as a strong default for common flows, not a universal control plane |
</threat_model>
