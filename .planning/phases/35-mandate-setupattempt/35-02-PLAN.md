## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer params -> Stripe endpoints | Caller-supplied IDs and filters cross into remote requests |
| Missing required scope filter -> local validation | SDK must decide whether to fail locally or defer to Stripe |
| `stripe-mock` behavior -> integration confidence | Integration infra can confirm routes but not every real-world semantic nuance |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-04 | R | `Mandate.retrieve/3` | mitigate | Keep the API retrieve-only, use the standard empty-param GET request shape, and unit-test endpoint routing explicitly. |
| T-35-05 | D | `SetupAttempt.list/3` and `stream!/3` | mitigate | Enforce `"setup_intent"` locally with `Resource.require_param!/3` so callers fail fast before a remote 400 and tests lock the exact error path. |
| T-35-06 | S | Integration confidence for SetupAttempt | mitigate | Use integration tests only for route sanity and keep parser semantics plus required-filter behavior under unit coverage as the primary correctness boundary. |
</threat_model>
