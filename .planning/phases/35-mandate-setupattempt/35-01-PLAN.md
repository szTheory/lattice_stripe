<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stripe JSON -> `from_map/1` | Untrusted remote payloads become typed SDK structs |
| Embedded historical error data -> application pattern matches | `setup_error` could be mistaken for the request-failure channel if modeled poorly |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-01 | T | `Mandate` and nested structs | mitigate | Use fixed `@known_fields`, explicit assignment, parse-time atomization of bounded enums, and `extra` preservation so unknown Stripe keys do not crash or create atoms dynamically. |
| T-35-02 | S | `ObjectTypes` registry and nested expandables | mitigate | Register only the exact new object types and keep `maybe_deserialize/1` behavior unchanged so unknown objects still remain raw maps. |
| T-35-03 | I | `SetupAttempt.SetupError` | mitigate | Keep `setup_error` as a dedicated nested struct rather than `%LatticeStripe.Error{}` so successful responses cannot be confused with transport/request failures. |
</threat_model>
