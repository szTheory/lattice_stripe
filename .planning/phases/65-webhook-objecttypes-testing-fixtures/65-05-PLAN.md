Create `lib/lattice_stripe/testing/fixtures/invoice.ex` defining
`LatticeStripe.Testing.Fixtures.Invoice` with a single builder `invoice_json(overrides \\ %{})`.

**Lift the body verbatim** from the private `defp invoice_json/1` in
`test/lattice_stripe/invoice_test.exs`. Do not re-invent, trim, or "improve" the field set. That
function's exact shape is what the file's roughly nineteen existing assertions were written
against; any change to a value or a nested structure turns this plan into a test-rewriting exercise.
The source is already in the public call form — `Map.merge(canonical, overrides)` as a call, not a
pipe — so it transfers cleanly. Preserve the nested `lines` envelope exactly as it is, including
its empty `"data"` list, its `"has_more" => false`, and its
`"/v1/invoices/in_test1234567890/lines"` url: the empty-collection default is the OBJ-03 empty-input
edge and is deliberate, not a placeholder to fill in.

Give the module a real `@moduledoc` in the established voice ("Canonical raw fixtures for Stripe
Invoice objects.") and a `@spec invoice_json(map()) :: map()`. `@moduledoc false` would satisfy
Credo's `Readability.ModuleDoc` and still make the module invisible in HexDocs (Pitfall 4).
Introduce no reference to `LatticeStripe.TestHelpers` — it lives in `test/support/` and is
unreachable from `lib/`; such a call fails `MIX_ENV=prod mix compile` (Pitfall 3). The `lines`
envelope is already built inline, so keep it inline.

**Run the secrets scrub (T-65-03)** on the new file before considering it done:
`grep -nE 'sk_live|pk_live|whsec_|rk_live|acct_1'`. Anything under `lib/` ships to hex.pm
irrevocably.

**Delete the private `defp invoice_json/1`** from `test/lattice_stripe/invoice_test.exs` and have
the file call the public fixture instead, so exactly one canonical invoice shape exists in the repo.
Leaving both would reproduce the `Dispute` drift hazard 65-PATTERNS.md § Anti-Precedent warns
against. Update every call site in that file. Do not otherwise modify its assertions — if any
assertion fails after the swap, the lift was not verbatim and the fixture is wrong, not the test.

Leave `invoice_json_for_telemetry/1` in `telemetry_test.exs` alone. It is a deliberately reduced
shape for telemetry assertions, not a canonical wire fixture, and publishing two competing invoice
fixtures would make the canonical one ambiguous.

**Add the typed wrapper — alias and wrapper in this same commit.** In
`lib/lattice_stripe/testing.ex`, extend the `alias LatticeStripe.{...}` block with `Invoice` in
alphabetical position and add an `invoice/1` wrapper in the `dispute/1` shape — `@doc`, `@spec`,
one-line delegation to `Invoice.from_map/1`. The name does not collide with anything existing in
that module. An alias landing ahead of its user fails `mix compile --warnings-as-errors`
(STATE `[63-01]`).

**Register with ExDoc and the guide.** Append `LatticeStripe.Testing.Fixtures.Invoice` to
`groups_for_modules[:Testing]` in `mix.exs`, add its bullet to the `guides/testing.md`
public-fixture list, and add `invoice/1` to the typed-struct wrapper sentence. Do not
backtick-autolink any `@moduledoc false` module — that raises the ExDoc warning count above the 38
baseline and fails gate steps 4 and 5.

**Add the surface locks.** Extend the existing `describe "public fixture builders"` and
`describe "typed wrappers"` blocks in `test/lattice_stripe/testing_test.exs` — do not add new
`describe` blocks. Assert `is_map(Fixtures.Invoice.invoice_json())`, assert the OBJ-03 empty edge
explicitly (the nested `lines` envelope has `"object" => "list"` and an empty `"data"` list by
default), and assert `%Invoice{} = Testing.invoice(Fixtures.Invoice.invoice_json())`. Add a
`docs_truth_test.exs` assertion that the module is in `docs[:groups_for_modules][:Testing]`.
