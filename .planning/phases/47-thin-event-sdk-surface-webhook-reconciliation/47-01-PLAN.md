## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Adversary-controlled JSON → `EventNotification.from_map/1` | Decoded payload may contain attacker-influenced keys (unknown extras, unexpected types). `from_map/1` is infallible-deserialize and pushes unknown fields into `extra` — no eval/no execution. |
| Stripe API → `Event.from_map/1` (v2-shape) | Stripe-controlled but wire shape can drift; new fields land in `extra` safely. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-47-01 | Information disclosure | `EventNotification` Inspect impl leaking sensitive fields | mitigate | Inspect hides `:extra` and `:reason` (reason contains idempotency_key + request_id); explicit refute test asserts no `"sk_"`, `"api_key"`, `"%LatticeStripe.Client"` substrings in inspect output (Pitfall 4 regression). |
| T-47-02 | Tampering | Malformed `related_object` map crashes `RelatedObject.from_map/1` | mitigate | `from_map(nil), do: nil` clause handles snapshot/missing case; `from_map(map) when is_map(map)` only matches maps — non-map inputs raise `FunctionClauseError` at decode boundary, fail closed. |
| T-47-03 | Tampering | Unknown `related_object.type` from Stripe causes downstream `CaseClauseError` | mitigate | `ObjectTypes.fetch_module/1` typed-gate exposes the dispatch miss as `:error`; plan 04's `fetch_related_object/3` converts to `{:error, {:unknown_object_type, type}}` BEFORE any HTTP call (D-05 fail-fast). |
| T-47-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan (per RESEARCH "Package Legitimacy Audit — Not applicable"). Phase 47 adds zero new deps. |
