<objective>
Turn MTR-04 from a claim into a proven behavior, and fix the one real bug this phase found in passing.

`guides/metering.md` has shipped a factually false statement since v1.1 — that integer payload values
trigger `meter_event_invalid_value` — and accrue, which pins `~> 1.1`, read that exact sentence and
dropped the host payload as a result. Plan 64-07 rewrites the prose. This plan supplies the tests that
make the corrected prose enforceable, because a grep is structurally incapable of catching "the prose
says something false" (D-26).

Purpose: every sentence 64-07 writes about the encoder must be backed by an assertion here, so the
documentation cannot silently rot again.

Output: the D-20 regex widening plus its regression test, and MTR-04's four encoder-truth tests.
</objective>

<assumption_delta_decision>
**Checkpoint:** assumption-delta scan fired `detected: true` (advisory, non-blocking) on one `chosen`-family
signal — the term `custom` in MTR-04's phrase *"arbitrary custom `payload` dimensions"*.

**Assessment:** The signal is a false positive for the purpose the checkpoint exists to serve. MTR-04 is a
**documentation** requirement whose entire content is *confirming a capability Stripe and this library
already have*. F-19 verified by direct execution at HEAD that `form_encoder.ex` is a generic recursive
flattener with no allowlist: three unrelated dimension keys and a 36-digit decimal string all survive
byte-exact. There is no identity model, no entity type, and no schema in this library that "custom
dimensions" could generalize — a `payload` is an opaque `map[string]string` passed through untouched from
`MeterEvent.create/3` to the wire. Stripe owns the only interpretation of those keys, and D-27 records the
hard limit: on the GA API you cannot even read usage back grouped by a custom dimension.

**Decision: `no-change`.** Nothing is promoted, generalized, or made configurable. Manufacturing a promotion
here would add a surface this phase's own scope fence forbids.
</assumption_delta_decision>
