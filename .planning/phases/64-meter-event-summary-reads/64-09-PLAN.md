<objective>
Prove the Stripe-side half of this phase against a real OpenAPI-validated server, lock the published-docs
placement of all five new modules, and clear the two pre-existing warnings that would otherwise force the
phase gate to use a fragile scoping rule.

Purpose: everything else in this phase is proven against a mock transport, which is correct — it is the
only place pagination and header survival are observable. But three claims can only be checked against a
server that validates against Stripe's actual OpenAPI spec: that the path exists, that the required
parameters are enforced in the order documented, and that a nested payload is rejected. That last one is
the check that would have caught the fact that this SDK will happily build a request Stripe refuses.

Output: the integration suite, the ExDoc placement assertions, and a warning baseline of 40.
</objective>
