<objective>
Type the `v1.billing.meter.error_report_triggered` payload end to end, so an operator who receives one can
answer "which meter, which window, which requests" without reaching into raw maps.

Purpose: this is the diagnose half of the metering surface. The payload has no endpoint, no id and no
object key, so it can never arrive through the webhook object registry — it must be decoded explicitly,
and the two shipped guides that teach otherwise are repaired in 64-07 and 64-08. The single highest-value
field is `SampleError.request_identifier`: the idempotency key of the failing write, and therefore the only
join back to the adopter's own database.

Output: four modules, a fixture seeded from the verbatim published payload, and a pure unit test suite
with no transport.
</objective>
