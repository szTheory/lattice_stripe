## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host Checkout request to SDK Client/Transport | Test request parameters enter the SDK encoder; only the explicit Mox transport returns a synthetic Stripe-shaped response. |
| Raw webhook request to verified Event handler | Untrusted raw bytes and Stripe-Signature cross the Phoenix Endpoint; the package Plug verifies the signature before typed event dispatch. |
| Hex dependencies to isolated host app | Phoenix/Plug/Mox are resolved into the adopter's lockfile without changing the published package runtime dependency surface. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-76-01 | Spoofing/Tampering | PhoenixAdopter.Endpoint webhook path | high | mitigate | Mount LatticeStripe.Webhook.Plug before Plug.Parsers, retain default timestamp tolerance, and assert signed success plus one-byte body tampering returns 400 before handler notification. |
| T-76-02 | Information disclosure | Host fixtures and README | medium | mitigate | Use fixed synthetic-only key, secret, and IDs in the test host; assert `livemode: false`; omit env lookup, raw-body logging, and persistent storage. |
| T-76-03 | Denial of service | Checkout outbound call | medium | mitigate | Inject the host Mox transport in an explicit Client with retries disabled; its request expectation fails if the intended SDK call is absent or changes contract, and no Finch request is used in the flow. |
| T-76-04 | Tampering | Host dependency resolution | low | mitigate | Resolve Phoenix and Mox from Hex into the adopter-local lockfile and keep the root package dependencies unchanged. The package-legitimacy automation is not defined for Hex packages. |
