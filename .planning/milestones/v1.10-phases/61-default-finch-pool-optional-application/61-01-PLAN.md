<objective>
Wire a zero-config default Finch pool end-to-end and relax the two `:finch` requirements, so a developer can make live Stripe calls without manually starting and wiring a Finch pool (DX-01, D-01..D-06).

Purpose: Closes the accrue-verified footgun (SEED-005 §3.1) — a consumer that never wires `:finch` currently raises `NimbleOptions.ValidationError` on every live call. The library ships an optional `LatticeStripe.Application` that starts a default `LatticeStripe.Finch` pool, and `:finch` defaults to that pool name.
Output: `lib/lattice_stripe/application.ex` (new), `mix.exs` (`mod:` wiring + ExDoc registration), relaxed `config.ex` + `client.ex`, and tests proving the happy path, backwards compatibility, and the opt-out.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-61-01 | Tampering | LatticeStripe.Application default pool startup | low | accept | The default pool uses Finch's own connection/TLS defaults (identical to a caller-started pool); starting it changes only pool *lifecycle*, not TLS/connection config. Honest low — no weakening of transport security. |
| T-61-02 | Denial of Service | Auto-started idle pool for BYO-supervision users | low | mitigate | Opt-out toggle `config :lattice_stripe, start_default_finch: false` (D-05) lets BYO-supervision users prevent a duplicate idle pool; documented in Plan 02. Worst case unmitigated is one idle default-sized Finch pool (~1 shard, no active connections) — acceptable per 61-CONTEXT.md Risks. |
| T-61-03 | Elevation of Privilege | Opt-out cannot silently disable HTTP | low | accept | Opt-out only prevents the *default* pool from starting; a caller passing an explicit `finch:` pool is unaffected. It cannot be exploited to silently disable HTTP for callers who wire their own pool. Honest low. |

Note: no package-manager installs this phase (zero new dependencies — Finch and NimbleOptions are pre-existing), so no `T-61-SC` supply-chain checkpoint applies.
