<objective>
Prove the entire Phase 65 mechanism end-to-end on ONE object type: `entitlements.active_entitlement`.

This is the phase's tracer. It wires a single Stripe object through every layer Phase 65 will
touch — the dispatch registry, the promoted public fixture, the typed wrapper, ExDoc registration,
the adopter-facing guide, and all three test surfaces — before any expansion plan repeats the
pattern for metering (65-02), core billing (65-03/65-05), or the remaining registry rows (65-04).

Purpose: the risky, unproven mechanism in this phase is not the registry row (one line). It is the
**promotion** — a file crossing from `test/support/` into `lib/`, which changes what compiles in
`:prod`, what ships in the Hex tarball, and what Credo and ExDoc apply to. Proving that on one
resource family first means an architectural dead-end costs one commit, not five.

Output: an adopter who installs the Hex package can call
`LatticeStripe.Testing.Fixtures.Entitlements.active_entitlement_json()` and round-trip it through
`LatticeStripe.ObjectTypes.maybe_deserialize/1` into a typed struct.
</objective>
