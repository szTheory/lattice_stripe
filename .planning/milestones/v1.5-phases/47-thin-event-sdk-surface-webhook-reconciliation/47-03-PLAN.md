<objective>
Reconcile the four-surface drift in `Webhook.check_tolerance/2` `tolerance: 0` semantics per D-03 (code-fix path). Today, the docstring at `lib/lattice_stripe/webhook.ex:84` says "Set `0` to disable staleness check" but the actual clause at `:268-273` returns `{:error, :timestamp_expired}`, and the Plug NimbleOptions schema at `lib/lattice_stripe/webhook/plug.ex:142-146` types `:tolerance` as `:pos_integer` (making `0` unreachable through the Plug entirely). The existing test at `test/lattice_stripe/webhook_test.exs:121` enshrines the wrong behavior by asserting `tolerance: 0` rejects.

This plan flips the code path to match the docstring intent (and matches every canonical Stripe SDK — stripe-node, stripe-go, stripe-ruby), relaxes the Plug schema to `:non_neg_integer` so `0` is reachable, rewrites the broken test, and adds a CHANGELOG entry + docs-truth regression test so the reconciliation stays locked.

Purpose: WEBFIX-01 is the v1.5 bug-fix requirement. RESEARCH Pitfall 5 warns that without an inline source comment + CHANGELOG + docs-truth grep test, this drift is likely to come back via a future "fix it to be stricter" PR. This plan is deliberately separate from the THIN-* helper plans — bounded blast radius, independent of plan 01/02, can run in Wave 1 in parallel with plan 01.
