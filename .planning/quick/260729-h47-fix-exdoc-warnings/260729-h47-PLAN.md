# Fix ExDoc warnings and close the CI gap

## Why

`mix ci` has been red on `docs --warnings-as-errors`. GitHub CI runs plain `mix docs`
(`ci.yml:260`), which exits 0 regardless — so the local gate is strictly stronger than the
required `ci-gate` lane and these warnings could never fail a PR. The asymmetry is the real
defect; the 9 warnings are its symptom. Fixing the warnings without closing the gap would leave
the next 9 free to accumulate.

18 warnings are emitted for 9 distinct causes: ExDoc runs the html and epub formatters and each
reports independently.

## Task 1 — Repoint two links at files that are not ExDoc extras

**files:** `guides/getting-started.md`, `guides/user-flows-and-jtbd.md`

`README.md` and `notebooks/stripe_explorer.livemd` exist on disk but are not in `mix.exs`
`extras:`, so ExDoc has no output page to resolve a relative link against. The sibling
`../CHANGELOG.md#200` on the same line does *not* warn, because `CHANGELOG.md` **is** an extra.

**action:** Use absolute GitHub URLs, do not add either file to `extras:`. Adding `README.md`
would duplicate the landing page against `main: "getting-started"` and require a
`groups_for_extras` entry. `docs_truth_test.exs:376-379` already establishes absolute URLs as the
convention "for hex.pm portability".

**constraint:** `getting-started.md:20` is a `**Current Hex line:**` release-status line rewritten
by `LatticeStripe.VersionProse`. Its `rewrite_release_status/3` matches the `` `2.0.x` `` token and
the `CHANGELOG.md#200` anchor — leave both byte-identical.

**verify:** `mix lattice_stripe.version_prose --check`

## Task 2 — Fully qualify `File.create/3`

**files:** `guides/recipes.md` (lines 49, 96)

Inside an extra there is no alias context, so `File` resolves to Elixir's stdlib `File`, which has
no `create/3`. The intended target is `LatticeStripe.File.create/3` (`lib/lattice_stripe/file.ex:111`,
public). This is a live reader-facing bug — the guide currently points at the wrong module.

**action:** `` `File.create/3` `` → `` `LatticeStripe.File.create/3` `` in both places.

## Task 3 — De-link five references from public docs into hidden internals

**files:** `lib/lattice_stripe/testing.ex`, `lib/mix/tasks/lattice_stripe.check_drift.ex`,
`lib/lattice_stripe/webhook.ex`, `lib/lattice_stripe/builders/billing_portal.ex`,
`lib/lattice_stripe/webhook/plug.ex`

Each backticks a `@moduledoc false` module, a `@doc false` function, or a `defp`. ExDoc is right
to warn: these are public docs sending adopters at things they cannot open.

**action:** Remove the backticks, keep the descriptive name as plain prose. Where the sentence
reads better without the internal name at all — `webhook.ex:376` especially, a *public*
function's doc — rephrase to describe the behaviour instead.

**Explicitly rejected:** promoting `LatticeStripe.ObjectTypes` or `BillingPortal.Guards` to
public. That is a one-way semver door, and would force regenerating `priv/api/current.txt` plus
adding a `groups_for_modules` entry. Adding permanent API commitments to silence a doc warning is
backwards.

**precedent:** `check_drift.ex:11` already writes "ObjectTypes registry" unbackticked in the same
moduledoc that warns three lines above; `webhook.ex:117` writes `check_tolerance/2` unprefixed and
does not warn.

**must not break:**
- `docs_truth_test.exs:899` — `assert guide =~ "fetch_related_object"`
- `docs_truth_test.exs:1148-1158` — `plug.ex` `@moduledoc` must still match
  `~r/@moduledoc.*tolerance.*0.*testing only/s`

**verify:** `mix lattice_stripe.api_surface --check` must still report **3427 entries**. That is
the proof this task de-linked rather than promoted.

## Task 4 — Make CI enforce it

**files:** `.github/workflows/ci.yml`, `CONTRIBUTING.md`

**action:** `ci.yml:260` `mix docs` → `mix docs --warnings-as-errors`. The `quality` job is already
a required `ci-gate` lane, so no gate-list edit and no new job is needed.

Leave `release.yml:378` and `publish-hex.yml:215` as plain `mix docs`: both run after `ci-gate`
has already proved the docs build clean, so failing a *publish* on a doc warning trades real
outage risk for no new signal.

Add a note to `CONTRIBUTING.md` near the existing docs guidance: doc warnings fail CI, and
references to `@moduledoc false` / `@doc false` / `defp` entities must not be backticked.

## Verification

```bash
mix docs --warnings-as-errors                     # zero warnings
mix test test/lattice_stripe/docs_truth_test.exs
mix lattice_stripe.version_prose --check
mix lattice_stripe.api_surface --check            # 3427 entries, unchanged
mix ci                                            # green end to end
```

Adversarial check: re-add one backticked hidden reference on a scratch branch and confirm the
`quality` lane now fails. A gate nobody has seen fail is not known to work.

## Out of scope

Do not push to `main`, do not merge, do not regenerate `priv/api/current.txt`, do not change any
`@moduledoc false` / `@doc false`.
