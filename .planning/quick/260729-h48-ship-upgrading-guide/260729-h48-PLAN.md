# Ship the orphaned 1.1 -> 1.7 upgrading guide

## Why

`guides/upgrading-1-1-to-1-7.md` (340 lines) was written and fully registered in `mix.exs`
during phase 62, but the commits never reached `origin/main` — they sat only in the local `main`
checkout, which read as 13 "pre-squash duplicate" commits. It was found during git cleanup and
preserved on `origin/phase-62-upgrading-guide` rather than discarded.

Finished, registered, adopter-facing work should not sit on an orphan branch.

## Tasks

1. Restore `guides/upgrading-1-1-to-1-7.md` onto current `main`.
2. Add a scope banner: the guide covers the `1.1 -> 1.7` leg only, its `~> 1.7` pin is deliberate
   history, and 2.0's single breaking change (test-fixture builder rename) is called out with a
   pointer to the CHANGELOG. Without this, a guide titled "Upgrading" that silently stops two
   majors back misleads.
3. Register in `mix.exs` — `extras:` plus its own `{"Upgrading", ...}` group.

## Safety

The guide contains `{:lattice_stripe, "~> 1.7"}`, which must NOT be rewritten to the current line.
Verified safe before shipping:

- `VersionProse.@install_surfaces` is an explicit 7-file allowlist; this guide is not on it.
- `docs_truth_test.exs` `@stale_release_status_claims` is asserted against `README.md` only.

Same class of hazard as the CHANGELOG history entries: a historical pin is correct and rewriting
it would falsify the record.

## Verify

`mix ci` green — notably `docs --warnings-as-errors`, which now gates CI, so any broken reference
in 340 unreviewed lines fails the build.
